# 突然の旅会2026 アプリ 要件定義(v0.4)

- 作成日: 2026-08-12 / 更新: 2026-08-12(挙動詳細6点が確定、主要仕様ほぼ確定)
- ステータス: 実装着手可能(残る確認事項は下記「未確定事項」2点のみ)
- UIモック: [`mock/tabikai2026-mock.html`](../mock/tabikai2026-mock.html)

## 概要

主催する団体旅行企画「突然の旅会2026」で使用する、参加者20〜25名向けのアプリ。
スマホベースのUI(PCレイアウトは管理者画面のみ)。

## 技術方針

### フェーズ1: Web版(PWA)を先行構築

- **スタック**: Next.js + Vercel + Neon(PostgreSQL)
- **最初からPWA対応**で構築し、Webプッシュ通知(Service Worker + VAPID)を実装する
  - iOS 16.4以降: ホーム画面に追加したPWAはWebプッシュ通知に対応
  - Android: ブラウザ/PWAともにWebプッシュ対応
- これで通知要件が満たせれば**ネイティブアプリは不要になる可能性が高い**

### フェーズ2(必要な場合のみ): ネイティブアプリ

- **iOS**: TestFlight含めApple Developer Program(年 $99)必須。無料での20名超配布は不可能
- **Android**: APK直接配布なら無料(Play Console利用時は買い切り $25)
- PWAで通知要件が満たせない・端末対応で問題が出た場合のみ判断する

## 用語の整理

「イベント」が2つの意味で使われるため、データ設計上は以下で区別する:

- **企画(Trip)**: 「突然の旅会2026」のような旅行企画全体。ロゴ・日程・メンバー・管理者を持つ最上位エンティティ
- **イベント(Event)**: 予定表に載る個々の予定(夕食、カラオケ等)。企画に属する

UI上の文言はどちらも「イベント」で問題ないが、コード・DBでは Trip / Event として分離する。

## 機能要件

### -1. マルチ企画対応・イベント選択 【確定】

- **管理者は複数の企画を作成できる**
- ログイン後のアプリトップは**イベント(企画)選択画面**: 自分が参加する企画の一覧から選択してダッシュボードへ
- 過去の企画(終了済み)も一覧に表示され、閲覧できる
- 管理者画面にも企画の切替セレクタを設置

### -0.5 ダッシュボード(ホーム画面) 【確定】

企画選択後のトップ画面。下部タブの先頭「ホーム」からもアクセス。

- **イベントロゴ**(+企画名・日程・参加人数、イベント切替ボタン)
- **次の予定**: 直近の参加登録済みイベント(開始までの残り時間つき)と招待中のイベント
- **未承認のコスト**: 自分が承認すべき費用の一覧と合計 → 承認画面へ

### 0. 認証・参加承認 【確定】

- **Googleアカウント(OAuth)でログイン**してユーザーを識別する
- 初回ログイン時は「参加承認待ち」状態となり、**管理者が管理画面で参加を承認**すると利用可能になる
- 承認されるまでアプリの機能は利用できない

### 1. 会場予約 / イベント機能 【確定: 予約=イベントは同一エンティティ】

- 会場×時間帯を指定して予約(=イベント作成)し、メンバーを招待できる
  - 作成時に「全員を招待」または個別選択が可能
  - 同一会場・同一時間帯の重複は作成不可(早い者勝ち)【確定】
- Microsoft Teams予定表風のUI: **列=会場、行=時間帯**のグリッドで日別表示
- 招待されたメンバーはイベント詳細から参加登録できる
- **主催者はイベント詳細から参加者を後から追加できる**(追加された人にはお知らせ+通知)
- 参加登録者にはイベント開始前にリマインド通知が届く

### 2. 費用入力(Walicaベース)

- 内容・金額・立替者を入力して費用を登録
- **「全員で割り勘」チェックボックス**: オンにすると名前入力を省略して全員均等割り、
  かつ**各メンバーの承認なし**でそのまま計上(確定)される
- チェックボックスがオフの場合は負担メンバーを個別選択
- **関連イベントを任意で紐付け**できる(仮)— 未承認時のエスカレーション先(イベント主催者)を特定するため

### 3. 費用承認

- 個別指定された費用は、割り勘対象の各メンバーが内容を確認して承認する
- 承認状況(例: 2/4)を費用一覧に表示。全員承認で確定ステータスに
- **未承認のまま24時間放置された場合**【確定】:
  - 本人へ催促のプッシュ通知を送信
  - イベント主催者(費用に関連イベントがある場合)および管理者へお知らせ経由で通知
  - イベント主催者または管理者が最終的な承認状況を操作できる(承認として確定 / 割り勘対象から外す)

### 3.5 精算 【確定】

- 管理者が管理画面で**「経費入力の締め」**を実行すると割り勘が確定する
- 締め後、**送金回数が最少になる精算リスト(誰が誰にいくら払うか)を自動計算**して表示
- 各メンバーの費用画面には自分の支払い先・金額を表示

### 4. 通知(プッシュ)

- **全体アナウンス**: 任意のタイミング・文面で全員に送信(例:「夕食が完成しました」)。**一般メンバーも送信可能**【確定】
- **イベントリマインド**: 参加登録したイベントの**開始5分前に自動送信。デフォルトはオン**で、イベント詳細から各個人がオン/オフできる【確定】
- **費用承認の催促**: 24時間未承認の対象者へ自動送信(3. 費用承認を参照)

### 5. お知らせ一覧

プッシュ通知の内容に加え、以下をアプリ内の一覧で確認できる:

- 自分が参加者に含まれるイベントが作成/招待されたとき
- 費用の割り勘対象に含まれたとき(→ そのまま承認画面へ遷移可能)
- 全体アナウンス、リマインドの履歴

### 5.5 持ち物リスト(必要なものの共有)

- 旅行に必要なものリストを**全体で共有**できる
- 誰でも項目を追加でき、各項目に「担当する(自分が持っていく)」を宣言できる(仮)
- 担当未定の項目が一目でわかる表示

### 6. 管理者機能(PCレイアウト)

- **イベントロゴの登録**: ダッシュボード・イベント選択画面に表示されるロゴをアップロード(PNG/JPG/SVG、推奨512×512px。未登録時は標準アイコン)【確定】
- **企画の作成・切替**: 複数企画を作成でき、管理画面内のセレクタで切替【確定】
- **旅行日程の設定**: 開始日時・終了日時を設定し、予定表の日付タブがこの範囲で自動生成される【確定】
- 会場(部屋)の作成・編集・削除
- 全イベントの編集・削除(主催者以外のイベントも含む)
- **メンバーの参加承認**(Googleログイン済みユーザーの参加リクエストを承認/拒否)
- **管理者の追加**: 招待URLを発行し、開いたメンバーが承諾すると管理者権限が付与される(複数人可)【確定】
- **経費入力の締め**と精算リストの公開
- 未承認費用の承認状況の操作(3. 費用承認を参照)
- 全体アナウンスの送信

## UI方針

- **お知らせは各画面ヘッダー右上のベルアイコン(未読バッジつき)から常時アクセス**(下部タブには置かない)
- 下部タブ: ホーム / 予定表 / 持ち物 / 費用 / 承認 の5つ
- **アイコンは絵文字を使わずSVGで描画**する(メッセージ本文等のユーザー入力内の絵文字は除く)

## 確定事項(2026-08-12 回答)

1. **予約とイベントの関係**: 同一エンティティとする(会場×時間帯の予約=イベント作成)
2. **認証方式**: Googleアカウントで識別し、管理者画面で参加を承認する方式
3. **精算機能**: 必要。管理者が経費入力を締めた後に精算リストを表示する
4. **お知らせ導線**: ヘッダーのベルアイコンに常時表示
5. **持ち物リスト**: 必要なものリストの全体共有機能を追加
6. **未承認費用の扱い**: 24時間放置で本人へ催促通知+イベント主催者・管理者へお知らせ。主催者または管理者が承認状況を操作できる
7. **リマインド**: 開始5分前固定・デフォルトオン。イベント詳細から各個人でオン/オフ可
8. **会場の重複予約**: 禁止(早い者勝ち)
9. **全体アナウンス**: 一般メンバーも送信可能
10. **旅行日程**: 管理者画面で開始日時・終了日時を設定
11. **管理者**: 複数可。招待URLを発行し、承諾したメンバーに管理者権限を付与
12. **ダッシュボード**: トップ画面にイベントロゴ・次の予定・未承認のコストを表示
13. **マルチ企画**: 管理者は複数イベント(企画)を作成可能。アプリトップにイベント選択画面を設置
14. **イベントロゴ登録**: 管理者画面から登録
